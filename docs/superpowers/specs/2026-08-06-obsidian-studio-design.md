# Stark Ye 黑曜科技网站与 Stark Studio 设计

日期：2026-08-06
状态：设计方向已确认，规格待用户复核
替代范围：本规格替代 `2026-08-06-personal-website-redesign.md` 中的视觉方向、主导航和手动内容维护流程；现有 Astro、Markdown、GitHub Actions、GitHub Pages、中英文策略与诚实空状态原则继续保留。

## 1. 背景与目标

现有 `starkye.com` 已由 Astro、Markdown、GitHub Actions 和 GitHub Pages 驱动，内容与部署链路已可用。下一阶段需要完成两项互相关联的升级：

1. 将明亮的 Creative Studio 视觉替换为已确认的黑金 `Obsidian Tech / 黑曜科技` 主题。
2. 增加只在本机运行的 `Stark Studio`，让网站所有常用内容都能在 Markdown 编辑器和实时预览中维护，并通过一个按钮安全发布。

目标受众仍是合作伙伴和技术同行。网站需要同时表达 AI 产品能力、全栈开发能力与个人判断，不依赖虚构项目、占位文章或公开内容后台。

## 2. 已确认的产品决策

- 对外名称：`Stark Ye`
- 网站标识：`SY`
- 视觉主题：方案 B `Obsidian Tech / 黑曜科技`
- Studio 图标：方案 A `金色轨道`
- 顶级栏目：首页、文章、项目、归档、关于我
- 联系方式：导航金色按钮、首页联系区和页脚，不占顶级栏目
- 内容编辑：Markdown 编辑器 + 实时预览
- 内容语言：中文优先，英文可选；未翻译内容可以独立发布
- 归档：文章和项目按年份统一汇总，并支持类型与标签筛选
- 发布：校验通过后直接提交并推送到远端 `main`
- Studio 管理范围：文章、项目、首页介绍、关于我和联系方式
- Studio 形态：本地 Web 应用，由带图标的轻量 macOS `.app` 启动器打开

## 3. 非目标

本阶段不包含：

- 公开网页后台、远程管理 API、数据库或用户账户
- 评论、会员、付费内容、联系表单或分析平台
- 全站自由文本搜索；归档页只提供类型与标签筛选
- AI 自动翻译或自动生成文章
- Electron、Tauri 等完整桌面运行时
- Windows 或 Linux 启动器
- 在 Studio 内自由修改导航结构、主题颜色或任意代码文件
- 虚构文章、项目或个人经历

这些能力以后只有在出现明确需求时才单独设计。

## 4. 信息架构

### 4.1 顶级导航

中文站：

- 首页 `/`
- 文章 `/articles/`
- 项目 `/projects/`
- 归档 `/archive/`
- 关于我 `/about/`

英文站对应使用 `/en/` 前缀。导航右侧保留 `中文 / EN` 切换和金色“联系我”按钮。

现有 `/contact/` 与 `/en/contact/` 作为辅助联系页保留，避免旧链接失效，但不显示为顶级栏目。RSS 继续作为文章页和页脚中的辅助入口。

### 4.2 首页顺序

首页保持已经验证的内容顺序：

1. Header
2. Hero
3. Articles Preview
4. Projects Preview
5. Contact CTA
6. Mini About
7. Footer

归档不在首页增加独立大区块。文章和项目区域的“查看全部”入口分别进入对应列表；页脚提供归档入口。

### 4.3 文章

`Thoughts` 对外统一改名为“文章 / Articles”，路由改为 `/articles/`，内容目录改为 `src/content/articles/`。当前没有正式文章，因此不需要内容迁移。原 `/thoughts/`、`/en/thoughts/` 与详情路由生成静态兼容页：设置新路由 canonical、执行即时客户端跳转，并始终保留可点击的新地址，避免直接出现 404。

文章列表按发布日期倒序排列，展示标题、摘要、日期、标签和语言。详情页支持 Markdown 正文、目录、更新时间、标签、上一篇/下一篇、可用译文入口和 RSS。

### 4.4 项目

项目列表与详情页继续由 Markdown 内容集合驱动。案例结构强调背景、关键判断、技术方案、职责和结果。没有真实项目时继续显示正式空状态，不生成示例卡片。

### 4.5 归档

归档页把当前语言下的非草稿文章与项目合并，按年份分组、日期倒序排列。用户可以按以下条件筛选：

- 全部 / 文章 / 项目
- 标签

筛选在浏览器端完成，初始 HTML 必须包含完整可读列表；关闭 JavaScript 后仍可浏览全部内容。首版不增加搜索框。

### 4.6 关于我与联系

About 页面包含简历摘要、当前关注、能力范围、做事原则和合作偏好。首页 Mini About 保持小型化并位于 Contact 之后。

联系入口统一使用 `yehanchen714@gmail.com`，支持打开邮件客户端与复制邮箱。导航中的“联系我”滚动到首页 Contact，其他页面则打开辅助联系页。

## 5. 黑曜科技视觉系统

### 5.1 色彩

核心设计令牌：

- 页面背景：`#070806`
- 一级表面：`#10110F`
- 二级表面：`#15140F`
- 主金色：`#E8B84F`
- 高亮金色：`#F7D985`
- 主文字：`#F6F1E8`
- 次要文字：`#9D9B94`
- 金色边线：`rgb(229 184 84 / 17%)`

金色只用于状态、主要操作、章节标签、关键字和少量边线。正文和大面积容器不得全部使用金色，避免降低可读性或产生廉价的“土豪金”效果。

### 5.2 字体与层级

- 英文大标题使用现有 Inter / 系统无衬线字体，重量 800 左右，紧凑字距。
- 中文使用 macOS 和主流系统的无衬线字体栈，不从第三方域名加载字体。
- 状态、编号和技术标签使用系统等宽字体。
- Hero 标题保持超大字号和紧凑行高；正文控制在舒适阅读宽度内。

### 5.3 表面与装饰

- Header 使用半透明黑色胶囊表面、细金边和轻微背景模糊。
- Hero 使用低对比度精密网格、金色径向光晕和轨道圆环。
- 卡片使用近黑渐变、细金边和极弱内高光。
- 主要按钮使用浅金到深金的渐变与深色文字；次要按钮只使用细边线。
- `SY` 仍是网站主标识，不引入尚未提供的个人照片。

### 5.4 动效

- Hover 与焦点过渡控制在 160–220ms。
- Hero 状态点允许低频脉冲；轨道允许非常缓慢的旋转或光点位移。
- 卡片 Hover 只做 1–3px 位移和边线亮度变化。
- 所有装饰动画在 `prefers-reduced-motion: reduce` 下关闭。
- 动画不承载内容或状态信息。

### 5.5 响应式与可访问性

- 桌面端保留超大 Hero 和右侧关注标签；移动端改为单列并缩短留白。
- 文字、按钮与焦点状态满足 WCAG AA 对比度。
- 金色按钮使用深色文字，不在金色底上使用低对比度白字。
- 键盘焦点采用可见的高亮金色轮廓。
- 空状态、筛选器、语言切换和复制邮箱均提供语义化标签。

## 6. 内容模型

### 6.1 文章与项目

文章保留以下字段：

- `title`
- `description`
- `publishedAt`
- `updatedAt`（可选）
- `tags`
- `language`：`zh` 或 `en`
- `draft`
- `translationKey`（可选）
- `cover`（可选）

项目保留现有字段，并增加可选 `cover`：

- `title`
- `summary`
- `publishedAt`
- `tags`
- `language`
- `featured`
- `draft`
- `translationKey`（可选）
- `links`
- `cover`（可选）

中文和英文条目可以独立存在。只有相同 `translationKey` 的两个条目才互相链接；缺少译文时不显示无效的语言切换入口。

### 6.2 站点文案

首页、About 与联系方式从 TypeScript 字典中迁移到受 schema 约束的结构化内容文件，使 Studio 可以安全修改文案而不编辑程序代码。固定使用：

- `src/content/site/zh.json`
- `src/content/site/en.json`

`zh.json` 与 `en.json` 都必须存在，以维持现有公共页面的完整双语体验；中文是默认编辑标签。文章和项目仍允许只创建中文条目，Studio 不自动翻译中文内容。

### 6.3 图片

Studio 接受 JPEG、PNG、WebP 和 AVIF。拖入后将文件名规范化，并保存到：

`public/uploads/YYYY/MM/<slug>-<filename>`

同名文件追加短哈希避免覆盖。单文件超过 2MB 时显示性能警告，超过 10MB 时阻止导入。首版不自动重编码或删除原图，避免有损处理和额外图像依赖。

## 7. Stark Studio 体验

### 7.1 启动

`Stark Studio.app` 是轻量 macOS App Bundle，不包含 Electron。启动器完成以下动作：

1. 定位个人网站仓库。
2. 检查 Node.js 24、Git 和依赖。
3. 在 `127.0.0.1` 的随机可用端口启动 Studio。
4. 打开带随机会话令牌的本地 URL。
5. 如果已有实例运行，则直接打开现有页面。

启动器使用选定的“金色轨道”图标，并生成 `.icns` 多尺寸资源。安装脚本固定把应用生成到 `~/Applications/Stark Studio.app`，不需要管理员权限。仓库移动后重新运行安装脚本，以更新启动器保存的仓库绝对路径。

### 7.2 主界面

主界面包含：

- Dashboard：最近草稿、已发布内容和发布状态
- Articles：文章列表、新建、复制、编辑和预览
- Projects：项目列表、新建、复制、编辑和预览
- Site：首页、About 与联系方式的结构化表单
- Settings：仓库位置、站点地址和发布前检查状态，只展示允许修改的设置

文章和项目编辑页左侧为 Markdown 编辑器，右侧为实时预览。标题、摘要、日期、标签、语言、草稿、封面和翻译关联使用独立字段，不要求用户手写 frontmatter。

### 7.3 草稿与保存

- 新内容创建时默认为 `draft: true`。
- 编辑内容会自动保存到对应 Markdown 或结构化内容文件。
- Studio 保存前使用 schema 校验，并采用临时文件 + 原子替换，避免半写入文件。
- 页面显示“已保存 / 正在保存 / 保存失败”状态。
- 关闭 Studio 不会删除本地草稿。
- 已发布文件的本地修改可以继续作为未发布草稿存在。

首版不实现自动云同步。Git 仍是已发布版本的历史记录。

## 8. Studio 技术架构

### 8.1 模块边界

Studio 使用 Node.js 24、TypeScript 和本地浏览器界面，放在同一仓库中：

- `studio/server`：本地 HTTP 服务、会话、静态资源和 API 路由
- `studio/ui`：Dashboard、列表、Markdown 编辑器、预览和状态界面
- `studio/content`：内容读写、slug、frontmatter、schema 与图片路径
- `studio/publish`：Git 预检、验证、提交和推送
- `studio/launcher`：macOS App Bundle、图标和安装脚本
- `src/lib/content-contracts`：网站与 Studio 共享的内容 schema 和类型

编辑器使用 CodeMirror 6。界面使用轻量 TypeScript 组件，不引入完整桌面框架。Markdown 预览复用网站设计令牌和正文样式，发布前仍以真实 Astro 构建为最终标准。

### 8.2 本地安全边界

- 服务只绑定 `127.0.0.1`，不监听局域网地址。
- 每次启动生成随机会话令牌；所有写入 API 校验令牌与 `Origin`。
- 服务设置严格 Content Security Policy。
- 文件 API 只允许访问已声明的内容目录和图片目录，拒绝路径穿越。
- Git 命令通过参数数组执行，不拼接 shell 字符串。
- Studio 不读取浏览器密码、GitHub Token 或其他无关文件。
- 同一仓库只允许一个 Studio 写入实例。

## 9. 一键发布流程

发布按钮执行以下顺序：

1. 保存当前编辑内容。
2. 校验必填字段、slug、翻译关联、图片路径和重复项。
3. 确认当前仓库基于最新的 `origin/main`；若远端领先则停止并提供“安全同步”入口。安全同步只在不存在 Studio 管理范围外的修改时启用：先把 Studio 修改保存到 `.stark-studio/recovery/<timestamp>/`，再以 fast-forward-only 方式更新本地分支，最后重新应用保存的内容；若同一文件发生冲突则停止并保留恢复副本，不自动选择任一版本。
4. 检查工作区。Studio 只允许暂存本次由 Studio 管理的内容和资源文件；检测到其他代码修改时停止发布并说明文件。
5. 执行 Astro/TypeScript 检查、内容测试和生产构建。
6. 使用明确的路径清单暂存文件。
7. 创建提交：`content: publish <type> <slug>`；站点文案使用 `content: update site copy`。
8. 推送当前提交到远端 `main`。
9. 显示提交 ID、GitHub Actions 链接和“查看线上网站”按钮。

不自动 force push，不自动解决合并冲突，不提交 Studio 以外的代码修改。任何一步失败都会停止后续步骤，保留本地内容，并显示可以理解的错误与重试入口。

## 10. 异常处理

- Node.js 版本不符：启动页给出检测结果和项目内正确运行时入口。
- Git 或远端不可用：允许继续写草稿，禁用发布并显示原因。
- Git 身份未配置：给出需要填写的姓名和邮箱，不代替用户猜测。
- 远端 `main` 已更新：先阻止推送；只有在工作区安全且能快进时才允许一键同步。
- 内容 schema 无效：定位到字段和文件，编辑器保留输入。
- slug 重复：阻止保存公开条目并建议可用 slug。
- 图片格式、大小或路径不合法：导入前阻止并说明限制。
- 构建或测试失败：不提交、不推送，展示失败命令和摘要。
- push 被拒绝或离线：提交保留在本地，提供重试，不重复创建提交。
- Studio 意外退出：已完成的原子保存仍在工作区，下次启动恢复。
- 端口占用：自动选择其他随机端口，不要求用户手动配置。
